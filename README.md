# 6TiSCH Multi-Layer Attack Dataset

Companion artefact for the paper **"A Multi-Layer Attack Dataset for Intrusion
Detection in IETF 6TiSCH Networks"** (Aydın, Aydın, Görmüş, 2026).

This repository contains the labelled telemetry dataset, the Cooja simulation
scenarios, the capture/generation harness, and the analysis pipeline required to
reproduce every table and figure in the paper.

---

## 1. Dataset overview

Seven attack families spanning five protocol planes of the IETF 6TiSCH stack:

| Plane | Attack | `attack_type` ID |
|---|---|---|
| Data | Blackhole | 1 |
| Routing | Decreased Rank | 2 |
| Control | DIS Flooding | 3 |
| Application | Application Flooding | 4 |
| MAC | TSCH Shared Cell Contention | 5 |
| MAC | 6P Cell Allocation Exhaustion | 6 |
| MAC | TSCH Desynchronization | 7 |
| (benign) | NONE | 0 |

Two topology scales share the same **placement-stratified design**:
7 attacks × 3 placements (core/mid/edge) × 2 attacker densities (1, 5) =
**42 runs per scale, 84 runs in total, ~872k labelled records**
(~362k @ 21-mote, ~510k @ 31-mote). Each run is a 60-minute headless Cooja
simulation; attack onset is randomised in [20, 25] min; telemetry is emitted
from the start (no warm-up suppression).

Two additional **pure-normal baseline** runs (zero attackers, one per scale,
~14.5k benign records) are provided as a benign anchor / false-positive
reference: `dataset/baseline/` (`*_baseline-n21-w0.log`, `*_baseline-n31-w1.log`).
They are generated by `capture/run_baseline.sh`, which marks every mote as a
normal client (empty attacker set), so no attack firmware is ever exercised.

### Headline result — difficulty spectrum

Under **group-aware** evaluation (LeaveOneGroupOut, group key `(run, node)`),
the seven families form a difficulty spectrum (Random Forest binary F1):

| Attack | 21-mote | 31-mote | |
|---|---|---|---|
| DIS Flooding | 0.98 | 0.80 | overt — near-trivial |
| 6P Cell Exhaustion | 0.93 | 0.89 | overt — near-trivial |
| Application Flooding | 0.70 | 0.72 | stealth |
| Blackhole | 0.48 | 0.45 | stealth |
| Decreased Rank | 0.27 | 0.46 | stealth |
| TSCH Desynchronization | 0.28 | 0.24 | stealth — hardest |
| TSCH Shared Cell | 0.18 | 0.24 | stealth — hardest |

Naive row-level k-fold inflates per-attack F1 by **up to +0.93** versus
group-aware evaluation: per-node identity leakage, not behavioural signal,
dominates the naive scores. **Always evaluate with group key `(run, node)`.**

## 2. Layout

```
dataset/
  21mote_a5/   21 logs (7 attacks × 3 placements, 5 attackers)
  21mote_a1/   21 logs (1 attacker)
  31mote_a5/   21 logs
  31mote_a1/   21 logs
  baseline/    2 pure-normal logs (0 attackers; 21- and 31-mote)
csc/
  21mote/      7 base Cooja scenarios (v3, 21-mote)
  31mote/      7 base Cooja scenarios (v3-30, 31-mote)
analysis/      ML evaluation + figure-generation scripts
capture/       telemetry capture + headless run/generation harness
REPRODUCING.md step-by-step reproduction guide
```

Figures are **not shipped**; they are regenerated from the dataset by the
`analysis/` scripts (see `REPRODUCING.md` §3).

### Log file naming

```
<YYYY-MM-DD>_<HH-MM-SS>_<attack>-n<nodes>-<placement>-a<density>-w<worker>.log
```
e.g. `2026-06-03_10-57-33_dis-n21-core-a5-w0.log`. Each log starts with a
`# run_metadata:` header recording attack, scale, placement, density, master
seed (42), worker id, and the exact attacker mote IDs.

## 3. Record schema (18 columns per row)

Rows appear as `b'<comma-separated ints>'`, emitted ~every 10 s by every mote.

| # | Column | # | Column |
|---|--------|---|--------|
| 0 | timestamp | 9 | tx_slot_count |
| 1 | node_id† | 10 | parent_switch_count |
| 2 | parent_id† | 11 | rssi |
| 3 | rank | 12 | route_count |
| 4 | buf_occupancy | 13 | delta_tx |
| 5 | dio_sent | 14 | delta_rx |
| 6 | dao_sent | 15 | app_packet_count |
| 7 | dis_sent | 16 | **is_attacker** (label) |
| 8 | nbr_count | 17 | **attack_type** (label) |

†`timestamp`/`node_id`/`parent_id` are for traceability and group-key
construction — **exclude them from the feature set** to avoid identity leakage.
